## insilicoPCR 0.15.4

This release fixes two mistakes 0.15.3 brought in, lets FASTQ runs write to a folder with `#` in its path, and checks the command line's inputs before it makes the output folder. On 2,022 Brucella assemblies and on the FASTQ samples it was checked with, its reports are those of 0.15.3. The full list is in [CHANGELOG.md](https://github.com/duceppemo/insilicoPCR/blob/master/CHANGELOG.md).

### Fixed

- **Primers overlapping head to head** (0.15.3): a primer's 5' bases that BLAST left out of its alignment let the other primer face it only where they pair with the template. A product whose primer ended on such bases that do not pair, which cannot be made, was reported.
- **Primers at contig ends** (0.15.3) named chance matches of 7 to 9 bases at a contig's end: all 71 warnings on 2,022 Brucella genomes, in place of the pairs 0.15.0 named. A primer cut by a contig end must now have at least 12 bases (or half its length) aligned on the contig: 7 warnings remain, 3 of them primer sites the assembly breaks inside. "At least N bp" counts the primer bases past the contig ends.
- **FASTQ: `#` in the output folder's path** failed every run with reads (BBTools wrote into `run12` and `run22` beside `run#2`).
- **Command line:** a primer file with a mistake, or an input that is not there, left an empty output folder behind; an output that is a file failed as "Unable to create directory". These are checked first, as in the window.
- **Application:** a run refused because another run holds the output folder no longer writes its lines into that run's `log.txt`.
- **Windows:** a junction where a run writes (`mklink /J`) and names that differ only in case (`Detailed_Report`) are refused as symbolic links are; `COM0`, `LPT0`, `CONIN$` and similar device names are left out with a message; accents in BLAST+ and BBTools messages show right in `cmd.exe`.

### Upgrading from 0.15.3

Results are those of 0.15.3, but for a product of primers overlapping head to head whose primer ended on 5' bases that do not pair: it is no longer reported. Also:

- Report files (`report.tsv`, `QAlog.txt` and the others) end their lines in LF on Windows too, as the HTML report did: a script that split them at CRLF there should split at LF.
- The HTML report lists at most 10,000 amplicons (50,000 in 0.15.3, a page that took some 40 seconds to open); `report.tsv` has every one.
- The application offers 0 to 10 mismatches (0 to 3 before).
- A sample whose file name has a `#` is left out of a FASTQ run, with a message.
